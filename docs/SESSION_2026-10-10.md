## 1. Quyền `telemetry/app/ping` — cơ chế và gia hạn

### 1.1 Nguyên nhân thật của 403

`POST /ccaraccessmgmt/api/v1/telemetry/app/ping` là nguồn **toạ độ / ODO / SOC /
quãng đường còn lại** khi xe đỗ. Đo 2026-10-10, cùng token, cùng body, cùng `X-HASH`:

| `X-Device-Identifier` | Kết quả |
|---|---|
| `8feb7998824e390b` (device app 2.26.11) | **200**, 100 key |
| `257ee177e21d6349` (giá trị hardcode cũ) | **403** Unauthorized |

Đổi token (app ↔ HA) **không** ảnh hưởng; đổi `X-APP-VERSION` **không** ảnh hưởng.
⇒ 403 **không** phải "TCU đang ngủ".

Hai điều kiện bắt buộc để ping 200:
1. **App VinFast đã đăng nhập** trên điện thoại (tạo phiên cho cặp tài khoản + device id).
2. **`X-VIN-CODE` đúng** — cùng token/khoá/device id, có VIN → 200, thiếu → 403.

### 1.2 Bảng đo — chỉ đăng nhập app mới tạo được grant

| Thời điểm | App | Thao tác | ping |
|---|---|---|---|
| 14:11 – 14:17 | đang đăng nhập | nhiều thử nghiệm | **200** |
| 15:38 – 15:46 | đã đăng xuất | — | **403** |
| 15:48 – 15:50 | đăng nhập | — | **200** |
| 15:55 | bị bridge đẩy ra | bridge đăng ký | **403** |
| 16:00 – 16:07 | đã đăng xuất | bridge đăng ký | **200** ← grant còn dư |
| 16:09 – 16:25 | đã đăng xuất | bridge đăng ký | **403** ← grant đã hết |
| 16:30 | **đăng nhập lại** | — | **200** (giả lập 18/18 PASS) |

**Kết luận:** grant do **app đăng nhập** tạo; TTL đo được **≈15 phút** sau khi phiên
kết thúc. Đăng ký qua bridge (`client/register` với Play Integrity token thật) **không**
tạo grant — các lần 16:00–16:07 thành công là do grant còn dư từ lần đăng nhập 15:58.
Tệ hơn: mỗi lần bridge đăng ký **đẩy app ra khỏi phiên**, làm grant hết sớm hơn.

### 1.3 Giải pháp: gia hạn bằng đăng nhập lại app

`/home/pi/vinfast/vf_grant_renew_app.py`

```
1. adb connect tới 6T
2. ping thử (khoá DB + VIN từ const)   -> 200 thì xong, không làm gì
3. xoá proxy (ĐỦ 5 khoá)                -> tránh app mất mạng
4. đổi IME sang AdbKeyboard             -> `input text` giữ đúng chữ hoa
5. force-stop + mở app, điền email/mật khẩu, gửi ENTER
6. xác nhận NewMainActivity (đã đăng nhập)
7. trả IME về Gboard
8. ping lại -> 200
```

Kiểm chứng trọn vòng:
```
16:45:48 ping trước: HTTP 403 (0 key)
16:45:49 đã xoá proxy (đủ 5 khoá)
16:46:36 app đã đăng nhập (NewMainActivity)
16:46:45 ping sau: HTTP 200 (2 key)
```

Triển khai: systemd `vinfast-grant-renew.service` + `.timer` (30 phút/lần, chạy bằng
user `pi` vì adb server thuộc user này). Service **kiểm tra trước**, grant còn tốt thì
không đăng nhập lại. Nên giảm chu kỳ còn **10–15 phút** vì TTL ≈15 phút.

Bản bridge cũ (`vf_grant_renew.py`) đã bị **thay khỏi systemd**; nó có sẵn chặn tần
suất `--min-interval-min` (mặc định 30) và `--force`.

## 2. `const.py` — những gì HA không tự lấy được

### 2.1 Phân loại

| Giá trị | Tự lấy? | Nguồn |
|---|---|---|
| VIN, `iotProvider`, session token EMQX, STS AWS | ✅ API | tự động |
| AWS IoT endpoint, Auth0 domain/client_id, API base | ❌ | `REGION_CONFIG` |
| **Host + port EMQX** | ❌ **không endpoint nào trả về** | `const.py` / UI |
| Bộ ba UAA, `X-Device-Identifier`, khoá RSA | ❌ (cần Play Integrity) | entry / DB |
| email, mật khẩu, token Mapbox/Stadia/Gemini | ❌ | config entry |

### 2.2 `const.py` gọn — chỉ thêm dòng HA dùng

Audit cho thấy khối `RENEWAL` (8 khoá) tôi từng thêm chỉ có **2 khoá** được HA đọc;
6 khoá còn lại là tham số vận hành của tiến trình ngoài (thuộc `vinfast_const.json`),
còn `vin`/`email` thì HA không đọc (nó lấy VIN từ API). Đã bỏ hết.

Kết quả: **101 → 72 dòng**, legacy giữ nguyên **20/20**, chỉ thêm:

```python
DEVICE_ID = "8feb7998824e390b"

DEVICE_ID_BY_EMAIL = {"thaitvad@gmail.com": "8feb7998824e390b"}

def device_id_for(email, fallback=None):
    mapped = {str(k).lower(): v for k, v in DEVICE_ID_BY_EMAIL.items()}
    return mapped.get(str(email or "").strip().lower()) or fallback or DEVICE_ID

def emqx_server(region="VN", options=None):
    rc = REGION_CONFIG.get(str(region or "VN").upper()) or REGION_CONFIG["VN"]
    opts = options or {}
    host = (str(opts.get(CONF_EMQX_HOST) or "").strip()
            or rc.get("EMQX_HOST") or "ccp-mqtt.vinfast.vn")
    try:
        port = int(opts.get(CONF_EMQX_PORT) or rc.get("EMQX_PORT") or 8884)
    except (TypeError, ValueError):
        port = int(rc.get("EMQX_PORT") or 8884)
    return host, port
```

**Tương thích ngược:** `api_auth._device_id()` bọc phần đọc const trong `try/except`,
nên const.py cũ (chưa có `device_id_for`) vẫn chạy và quay về `DEVICE_ID`.

### 2.3 MQTT server giờ cấu hình được từ UI

### 3.1 Lỗi trùng lặp trong bản xuất — đã vá

**Triệu chứng:** `CONF_UAA_CLIENT_INSTANCE_ID` bị ghi giá trị UAA thay vì tên khoá
option → `config_flow` đọc sai khoá ⇒ hỏng tích hợp.

**Nguyên nhân:** mẫu không neo `({field}\s*=\s*")[^"]*(")` khớp **cả**
`CONF_UAA_CLIENT_INSTANCE_ID = "` (vì chuỗi `UAA_CLIENT_INSTANCE_ID = "` nằm bên trong)
**lẫn** dòng UAA thật; `re.sub` **không có `count`** nên thay cả hai.

**Thuốc:**
```python
pattern = rf'(?m)^(?<![A-Za-z0-9_])({field}\s*=\s*")[^"]*(")'
text = re.sub(pattern, ..., text, count=1)
```

Kiểm chứng: `CONF_*` giữ đúng tên khoá, `UAA_*` giữ giá trị thật, không trùng lặp,
EMQX có mặt, file import được — **TẤT CẢ PASS**, `standard=True pem_ok=True`.

Quét 204 file `const*.py`: 7 file lỗi, **tất cả trong `test_exports/`**, đã sửa 7/7.
